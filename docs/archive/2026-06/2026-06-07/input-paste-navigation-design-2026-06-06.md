# Input Box Paste and Navigation Improvements

> **Status: Done**

## Problem

The TUI input box has three concrete UX problems:

1. Large bracketed text paste expands into many editor lines and pushes the input
   area/status bar out of view.
2. Up/Down arrows always use command history when no panel is active, so users
   cannot move vertically inside multiline drafts.
3. Clipboard image paste inserts raw internal tokens such as
   `[image-clipboard-20260606-abc12345]`, which are functional but not readable.

There is also a broader transcript display concern for pasted content. V1 treats
that as a pipeline verification problem: draft tokens must be expanded before
the agent and attachment parser see the message.

## V1 Scope

In scope:

- Collapse large pasted text into one visible draft token.
- Preserve the full pasted text internally and expand it on submit.
- Keep Ctrl-C interruption restore compact instead of restoring the expanded
  large text into the input box.
- Display pasted images as readable draft tokens while expanding them back to
  `[image-stem]` on submit.
- Treat `Ctrl+V` as a universal clipboard paste path: prefer image content, then
  fall back to macOS clipboard text.
- Make Up/Down move inside multiline drafts before falling through to history.
- Style collapsed paste/image tokens in the input renderer.
- Add focused PureTui tests for submit, restore, navigation, rendering, and
  image expansion.

Out of scope:

- Editing inside a collapsed paste token.
- Persisting paste registries across sessions.
- Web UI or desktop UI paste handling.
- Drag-and-drop attachments.
- Full transcript preview redesign.

## Core Model

V1 distinguishes three values:

- `draft_text`: what the input editor stores and renders. This may contain
  visible tokens such as `[Pasted text #1 +34 lines]`.
- `submit_text`: what gets queued for the agent. All registered paste/image
  tokens are expanded before queueing.
- `restore_text`: what should return to the input box if the running turn is
  interrupted. This stays equal to `draft_text`.

The input box must never depend on the expanded message for restore. Otherwise a
large paste would re-expand into many input lines after Ctrl-C.

## Paste Registry

Add per-input registries to `PureTui`:

```python
self._paste_entries: list[dict[str, object]] = []
self._paste_next_id: int = 1
```

Each entry:

```python
{
    "id": 1,
    "kind": "text" | "image",
    "display": "[Pasted text #1 +34 lines]",
    "expanded": "full text or [image-stem]",
}
```

Visible text is not a global protocol. A token expands only if it exactly
matches an entry in the current registry snapshot. User-typed lookalikes do not
expand unless they were generated by the current input state.

Registry lifecycle:

- Normal editing keeps the registry.
- Deleting or replacing a token line leaves an orphaned entry, which is harmless
  because expansion only replaces displays still present in the draft.
- `_clear_input()` clears the active draft registry.
- Submit captures a registry snapshot before clearing input.
- `_consume()` keeps that snapshot with the running turn.
- Normal completion drops it.
- Ctrl-C interruption restores `restore_text` and the snapshot.

## Text Paste Collapse

`_insert_pasted_text()` normalizes line endings. It collapses text when either
condition is true:

- more than 3 lines;
- more than 200 characters.

Short pastes keep the current behavior and insert verbatim.

For collapsed paste:

1. Register the full normalized text.
2. Insert one display token at the cursor.
3. Place the cursor after the token.
4. Do not split the paste into editor lines.

Display format:

- Multiline: `[Pasted text #N +M lines]`, where `M = total_lines - 1`.
- Single long line: `[Pasted text #N 240 chars]`.

Submit expansion walks the active submit snapshot and replaces exact `display`
strings with `expanded`.

## Image Paste Display

Current clipboard image paste saves the file and inserts `[image-stem]`. V1
keeps `[image-stem]` as the submit protocol, but inserts a readable draft token:

```text
[Pasted image #1 142KB]
```

The registry entry stores:

```python
{
    "id": 1,
    "kind": "image",
    "display": "[Pasted image #1 142KB]",
    "expanded": "[image-clipboard-20260606-abc12345]",
}
```

The input also appends a trailing space after the image display token, matching
the current raw image-token behavior.

## Submit and Restore Flow

`_do_submit()`:

1. `draft_text = _get_input_text()`
2. `submit_text = _expand_registered_tokens(draft_text, self._paste_entries)`
3. `_record_history(draft_text)`
4. Capture `restore_text = draft_text` and `registry_snapshot`.
5. `_clear_input()`
6. Queue `submit_text`.
7. Store the restore payload for `_consume()`.

`_consume()`:

- sets `_current_submitted_text` to `restore_text`, not `submit_text`;
- stores `_current_submitted_paste_entries` for interruption restore;
- calls `on_submit(submit_text)`.

`_restore_interrupted_input()`:

- restores `_input_lines` from `_current_submitted_text`;
- restores `_paste_entries` from `_current_submitted_paste_entries`;
- puts the cursor at the end of the restored draft.

External web submissions remain plain strings and have no restore registry.

## Multiline Arrow Navigation

When no choice, attachment panel, or command panel is active:

- Up moves to the previous input line if `_cursor_row > 0`.
- Up falls through to history only on the first line.
- Down moves to the next input line if `_cursor_row < len(_input_lines) - 1`.
- Down falls through to history only on the last line.

Column behavior:

- Keep the current column where possible.
- Clamp to the target line length when the target line is shorter.

Add helpers:

```python
def _cursor_up_or_history(self) -> None: ...
def _cursor_down_or_history(self) -> None: ...
def _clamp_cursor_col(self) -> None: ...
```

This keeps `parser.py` small and leaves editor behavior in `input.py`.

## Rendering

`_input_display_text()` stays string-only. Styling belongs in
`_render_input_line()`.

Renderer behavior:

- Split each input line into segments.
- Segments matching current registered paste/image display tokens use dim cyan.
- Ordinary text remains white.
- Cursor rendering still uses reverse video on the active character.

The segment split should be based on exact current registry display strings, not
a broad regex.

## Transcript Pipeline Verification

V1 does not redesign `dock.start_turn()` preview. It verifies that the pipeline
receives expanded text:

1. draft token in TUI input;
2. submit expansion before `_queue`;
3. image display token expands to `[image-stem]`;
4. `build_user_message_payload()` can parse the image attachment token.

If transcript truncation still feels poor after V1, handle it in a separate
spec with a concrete reproduction and preview format.
